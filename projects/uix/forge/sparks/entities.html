Entities Spark ​

Verfügbar ab UIX 9.2.0-beta.3

Entwicklungsfunktion; stabile Basis dieser Dokumentation bleibt 9.1.0.

Der Entities Spark füllt eine Entities-Karte mit gefilterten Entitäten, erzeugt ein Tile-Raster für einen Raum oder sammelt IDs für einen anderen Spark. Die Regeln stammen aus dem Lint-Free-Technology-Fork von auto-entities.

Karten ohne auto-entities-Hülle erzeugen ​

Das Grid zeigt für jede Entität im Schlafzimmer eine Tile-Karte und überspringt den Zustand unavailable. Ersetze bedroom durch einen eigenen Bereich. path: /cards füllt die Grid-Liste cards; das Spark-element liefert die Tile-Konfiguration. Forge setzt jeweils deren entity.

yaml
type: custom:uix-forge
forge:
  mold: card
  sparks:
    - type: entities
      path: /cards
      element:
        type: tile
      filter:
        include:
          - area: bedroom
        exclude:
          - state: unavailable
element:
  type: grid
  columns: 2
  square: false
  cards: []

Spark-Optionen ​

OptionTypStandardBeschreibung
typeZeichenfolge—Pflichtwert entities.
id / spark_idZeichenfolge—Spark-ID für Foundries, Untersuchung und Abfrageergebnisse. Ohne path erforderlich.
pathJSON Pointer—Zielliste in Forge-element, etwa /entities oder /cards. Forge erzeugt die Liste, wenn deren übergeordnetes Objekt existiert. Für reine ID-Abfragen weglassen.
modeappend, prepend, replaceappendEinträge hinten, vorne oder anstelle vorhandener Einträge einsetzen. Pro Entitäts-ID gewinnt der erste Eintrag.
entitiesListe von Entitäts-IDs—Explizite IDs vor den Einschlussfiltern hinzufügen. Ausschlussfilter können auch diese IDs entfernen.
filter.includeFilterliste—Entitäten hinzufügen, die mindestens einen Filter erfüllen. [{}] beginnt mit allen für den Benutzer verfügbaren Entitäten.
filter.excludeFilterliste—Nach expliziten IDs und Einschlussfiltern passende Entitäten entfernen.
sortMapping oder Mapping-Liste—Einträge sortieren, gruppieren oder begrenzen; siehe Gruppierung.
elementMapping—Für jede gewählte Entität zu kopierende Konfiguration. Ohne diesen Wert werden reine IDs geschrieben.
entity_pathJSON Pointer/entityStelle für die ID innerhalb jeder Kopie des Spark-element.

Bei mode: append oder mode: prepend müssen vorhandene Einträge zum erzeugten Format passen: Zeichenfolgen zu Zeichenfolgen, Mappings zu Mappings. Bei Mappings muss die ID unter demselben entity_path liegen. Vorhandene Trennlinien und Abschnittszeilen werden unterstützt.

mode: replace ersetzt die gesamte Liste.

Filter ​

filter.include fügt Entitäten hinzu, die mindestens einen Einschlussfilter erfüllen. filter.exclude entfernt danach alle zu einem Ausschlussfilter passenden Entitäten. Innerhalb eines Eintrags müssen alle Regeln passen. Gesucht wird nur unter Entitäten, für die HA dem aktuellen Benutzer einen Zustand bereitstellt.

Textregeln unterstützen genaue Namen, Platzhalter in Anführungszeichen wie entity_id: "sensor.*_battery" und reguläre Ausdrücke zwischen Schrägstrichen. Numerische Vergleiche stehen ebenfalls in Anführungszeichen, etwa ">= 20". $$ vor einem Muster vergleicht den Wert als JSON, etwa ein Listenattribut. Textregeln passen nur, wenn das Feld einen Wert hat: area: "*" wählt Entitäten mit Bereichszuordnung. Auch das active_choice-Format des auto-entities-Editors ist möglich.

RegelVergleich
domainTeil der ID vor dem Punkt, etwa light in light.kitchen.
entity_idVollständige Entitäts-ID.
nameAnzeigename der Entität.
stateAktueller Zustand. Liste für mehrere Zustandsbedingungen oder Mapping zum Vergleich mit einer anderen Entität.
state_translatedZustand in der HA-Sprache. Für Zahlenvergleiche state verwenden.
attributesMapping aus Attributnamen und Werten; alle müssen passen. : adressiert verschachtelte Attribute.
groupDirekte Gruppenmitglieder, etwa group.office oder eine Lichtgruppe.
group_expandedGruppenmitglieder einschließlich aufgelöster Untergruppen.
areaBereichsname oder -ID einschließlich vom Gerät geerbter Bereiche.
floorEtagenname oder -ID anhand des eigenen oder geerbten Bereichs.
levelNumerische Etagenebene, etwa ">= 1".
deviceGeräte-ID, benutzerdefinierter oder ursprünglicher Gerätename.
device_manufacturer / device_modelHersteller oder Modell des zugeordneten Geräts.
labelLabelname oder -ID an Entität oder Gerät.
integrationIntegrationsname, etwa browser_mod, oder ID eines bestimmten Konfigurationseintrags.
hidden_byVon user oder integration ausgeblendet. Ein Zustand muss trotzdem vorhanden sein.
entity_categoryKategorie im Entitätsregister, etwa config oder diagnostic.
last_changed / last_updated / last_triggeredZeit seit Änderung, Aktualisierung oder Automation. "< 15" bedeutet weniger als 15 Minuten, "< 2 h ago" weniger als zwei Stunden.
andAlle verschachtelten Filter müssen passen.
orMindestens ein verschachtelter Filter muss passen.
notDer eine verschachtelte Filter darf nicht passen.

Beispiel: Batterieentitäten der Garage einschließen und unavailable ausschließen.

yaml
filter:
  include:
    - area: Garage
      attributes:
        device_class: battery
  exclude:
    - state: unavailable

Beim Umstieg von auto-entities kommen die Entitätsregeln nach filter und das Listenziel nach path. Das Spark-element enthält Einstellungen für jeden erzeugten Eintrag. Für unterschiedlich konfigurierte oder sortierte Gruppen separate Sparks verwenden.

Entitätszeilen ohne auto-entities erzeugen ​

Für eine gewöhnliche gefilterte Entities-Karte das Spark-element weglassen. Forge schreibt die ausgewählten IDs direkt in die Kartenliste entities.

yaml
type: custom:uix-forge
forge:
  mold: card
  sparks:
    - type: entities
      path: /entities
      filter:
        include:
          - attributes:
              device_class: battery
        exclude:
          - state: unavailable
      sort:
        method: name
element:
  type: entities
  title: Batteries
  entities: []

Entitäts-IDs an anderer Stelle schreiben ​

Speichert das Schema die ID nicht unter /entity, setze entity_path als JSON Pointer relativ zu jedem erzeugten Mapping.

yaml
- type: entities
  path: /some_list
  element:
    target: {}
  entity_path: /target/entity_id
  filter:
    include:

Entitätszeilen gruppieren ​

sort.method legt eine Sortierung fest; eine Liste erlaubt mehrere Stufen nach Priorität. Methoden: none, domain, entity_id, name, friendly_name, device, area, state, attribute, last_changed, last_updated, last_triggered. Bei method: attribute zusätzlich den Attributpfad setzen.

Jede Stufe unterstützt reverse, ignore_case, ip und numeric. numeric: nan_first beziehungsweise numeric: nan_last ordnet nichtnumerische Werte vorne oder hinten ein. count: 5 auf der ersten Stufe begrenzt auf fünf Treffer. first überspringt vorher Einträge. Diese Optionen begrenzen die erzeugte Liste; benannte Abfrageergebnisse enthalten weiterhin alle gewählten IDs.

divider: true fügt Trennlinien zwischen Gruppen ein. section: true fügt vor jeder Gruppe einschließlich der ersten eine Überschrift ein und hat an derselben Stelle Vorrang. Für Listen mit Entitätszeilen verwenden, etwa Entities-Karten oder custom:fold-entity-row. Beim Gruppieren das Spark-element weglassen.

Überschrift vor jeder Gruppe ​

Ohne label verwendet eine Überschrift den Sortierwert der Gruppe. Mit label wählst du Namensbestandteile der ersten Entität: entity, device, area, floor oder wörtlichen text. separator bestimmt den Text zwischen den Teilen.

yaml
type: custom:uix-forge
forge:
  mold: card
  sparks:
    - type: entities
      path: /entities
      filter:
        include:
          - domain: sensor
      sort:
        - method: area
          section: true
          label:
            - type: text
              text: "Area: "
            - area
          separator: ""
        - method: name
element:
  type: entities
  title: Sensors by area
  entities: []

Abfrageergebnis wiederverwenden ​

Um IDs für andere Sparks oder Templates zu sammeln, vergib eine eindeutige id und lasse path weg. Dieser Spark dient nur der Abfrage: Er akzeptiert entities und filter und verändert die Forge-Konfiguration nicht. Schreibeinstellungen mode, sort, element und entity_path weglassen.

Ziel für die IDsVerwendung
Configuration Spark$in_entities: <id> mit einem benannten Entities Spark derselben Forge. Dieser darf auch nach path schreiben.
Home Summary Spark$in_entities: <id> mit einem reinen Abfrage-Spark derselben Card Forge.
Forge-Element- oder Hüllen-Styling-TemplateuixForge.entities["<id>"] eines reinen Abfrage-Sparks derselben Forge lesen.

Abfrageergebnis in Templates verwenden ​

Die Shortcut-Karte zeigt die Anzahl der Entitäten mit dem Label excluded_from_maintenance. Ihre Beschreibung wird bei Listenänderungen aktualisiert. Eckige Klammern funktionieren auch für IDs mit Bindestrichen.

yaml
type: custom:uix-forge
forge:
  mold: card
  sparks:
    - type: entities
      id: excluded_from_maintenance
      filter:
        include:
          - label: excluded_from_maintenance
element:
  type: shortcut
  label: Maintenance exclusions
  description: >-
    {{ uixForge.entities["excluded_from_maintenance"] | count }} excluded entities

Liste untersuchen ​

uix_entities_inspect in der Browserkonsole zeigt ausgewählte Entitäten und die erzeugte Liste. Der letzte Bericht liegt auf window.uix_inspect.entities: ids enthält IDs, entries die erzeugten Einträge und counts die Treffer je Einschlussfilter vor Ausschlüssen. Siehe Entities-Inspektor.

Für sichtbare Forge-Elemente deren <uix-forge> in DevTools unter Elements auswählen und die Befehle in Console ausführen. $0 bezeichnet die Auswahl.

js
await uix_entities_inspect($0);
window.uix_inspect.entities.ids;
1
2

Bei mehreren Entities Sparks dessen id oder spark_id als zweites Argument übergeben, etwa await uix_entities_inspect($0, "excluded_from_maintenance"). Alternativ eine Position ab 0 für den ersten Entities Spark angeben.

Für eine Strategie deren Forge-Einstellungen als JavaScript-Objekt übergeben, beginnend mit type: custom:uix-forge innerhalb von strategy: im Dashboard-YAML. Hier die Wartungsstrategie des gefilterten Home-Dashboards, wenn die Foundry bereits existiert.

js
await uix_entities_inspect({
  type: "custom:uix-forge",
  foundry: "maintenance-exclusions",
  forge: { mold: "strategy" },
  element: { type: "maintenance" },
}, "excluded_from_maintenance");
window.uix_inspect.entities.ids;
