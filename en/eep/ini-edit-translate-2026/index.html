Version 2.1.55: external CSV dictionary with read priority ​

The default dictionary includes the user's 30 reference terms in German, English, French and Polish, with corrected accents and special characters. The first start creates an external semicolon-separated UTF-8 CSV: %LOCALAPPDATA%\UGSo\IET2026\translation-dictionary.csv.

Add rows or correct translations. Each new translation reloads the file. Matching external entries take priority over the embedded seed list, existing model vocabulary and the selected online provider. Whole phrases work in all four source languages. Fully covered texts require no online request. Unknown proper names in model names remain unchanged. Empty target cells use the fallback. Missing, unreadable or malformed files remain untouched; the embedded seed list remains available. Online results are never automatically written to the CSV. Files up to 1 MiB and 2,000 data rows are read; each cell allows up to 200 characters without control characters.

Updates never overwrite an existing user CSV. Settings, credentials, custom entries, the Info_trans database and reference tables are retained. DR, DB, constructor codes, technical types, underscore identifiers, version notes and [e] remain protected, even against conflicting CSV entries. The seed list is embedded and written externally only at startup, keeping the update ZIP compatible with older updaters.

Info_trans adds the Railway abbreviations tab with 14 entries: Bf, Hbf, Hp, Gbf, Rbf, Abzw, BÜ, Stw, EG, OL, Gl., Bstg., DWW and Kr. The table shows German, English, French and Polish, including documented foreign abbreviations. The previously empty Kr. row is completed for a track crossing. Clicking a cell copies its contents, as in the existing reference tables. The table is read-only, columns can be sorted and long text wraps. The German tab name is Bahnabkürzung; the French name is Abréviations ferroviaires. The table is embedded in Info_trans. An existing external help/railway-abbreviations.csv can still be used. This reference table does not change automatic translation rules. Backup created before changes; dictionary, database, settings, credentials and the external constructor list are retained. The update ZIP uses only paths accepted by the 2.1.53 updater. Download and package validation are separate phases; 100% is shown only after successful validation. The dialog shows failure details and allows retrying. Both projects retain .NET Framework 4.8 and use a Framework Visual Studio designer. Info_trans explicitly references System.Configuration. Reload the solution after these changes. Design-time compilation and WinForms DesignSurface loading were checked; Visual Studio itself was not controlled remotely.

114 local checks passed, including table contents and DE/EN/FR layout at 100 and 150 percent scaling, without live API calls.

The supplied initial list contains 272 unique three-character constructor identifiers. The first application start creates an external UTF-8 file: %LOCALAPPDATA%\UGSo\IET2026\constructor-codes.txt. Blank lines, comments and invalid entries are ignored. Unreadable files are retained and the base list remains available as a fallback. Identifiers are retained anywhere, with or without parentheses. Generic recognition of additional identifiers remains active. DR, DB, type labels, version notes such as (V8) or (v8.2), EEP versions and [e] remain unchanged.

Version 2.1.52: descriptive words in model names ​

Descriptive words are now translated in model names, including when descriptions are empty. “Haus Helios Typ4 UD1” becomes House / Maison / Dom Helios Typ4 UD1.

Name translation uses a limited, reviewed local word list to protect proper names. Unknown words and name components are retained and never sent to an online service for name translation. This is not general automatic proper-name recognition: additional descriptive words require review. Existing names without a recognized descriptive component are not overwritten. Type labels, constructor codes, EEP versions, [e], separators and the spelling of protected components are retained. The railway abbreviations still being collected are not added in this change.

Descriptions still use the selected provider. Model names and descriptions are applied together only after success; failures retain existing contents. The provider-neutral button is now Translate texts.

MyMemory/translated.net is the default for new configurations. Existing provider choices, API keys, accounts and models are retained. To switch deliberately, choose About → Settings → Translation settings → MyMemory → Save.

105 local checks passed, covering DE/EN/FR/PL, empty descriptions, protected names and codes, failure handling and save/reload. Backup created; original files and credentials retained.

Version 2.1.51: folder-selection hint ​

Selecting a folder in the tree shows “Please select an INI file.” Loaded model texts, tables, preview and selected file are retained. A directory is no longer read as a file and no translation is started.

This applies to the root and arbitrary subfolders, including folders named with an .ini extension. Missing files and other file types show the same selection hint. Only an existing INI file is opened; uppercase .INI is supported too. The selected tree node is used instead of the pointer position, including keyboard navigation. The hint is available in German, English and French.

101 local checks passed, including retained data on folder selection in all three languages and opening an INI without pointer hit testing. Backup created; personal data and credentials are retained.

Version 2.1.50: protect EEP controls, constructor codes and versions ​

[e] remains an EEP line-break control, never a translated word or an actual newline. Exact spelling, count and order of protected markers are validated.

Constructor codes are recognized by letter/digit patterns without a fixed name list, including (GK3), (AG3), (DL1) and legacy bare codes at the start, middle or end. No code is added when none exists. Ordinary additions such as (Winter) remain translatable. Unusual letter-only codes cannot reliably be distinguished from ordinary words without an additional list.

Game versions such as EEP16.2, eep16.2 and EEP 16.2 retain their case and punctuation. MyMemory never receives protected segments for translation; changed or invented codes and controls in OpenAI/ChatGPT results are rejected. Existing rollback remains active.

A configuration entry introduced in 2.1.49 could prevent application startup. This is fixed and covered by a test of the shipped configuration. If 2.1.49 does not start: Back up INI Edit Translate 2026.exe.config, download the additional configuration asset from release 2.1.50, rename it to INI Edit Translate 2026.exe.config and replace the file beside the EXE. Start the editor and install the normal 2.1.50 update. Do not replace INI files, databases or personal settings.

99 local checks passed. An isolated installation test containing a leading code, game version, parenthesized code and two [e] controls was translated through real MyMemory calls, saved and reloaded. Original files and credentials are retained.

Translation providers ​

Select OpenAI API, ChatGPT plan or MyMemory under Options → Translation settings. MyMemory requires internet access but no key or account. An optional email address is sent with each request: the provider allows 5,000 characters daily anonymously, up to 50,000 with a valid email. Each target language counts separately. Long text is split into sections up to 500 UTF-8 bytes. A temporary cache avoids repeats within one operation.

German is the default. The selected interface language sets the initial source language; axes/signal functions retain their source selector. German and French are translated to English first; other target languages use that English intermediate text. This applies to all providers. The selected source text and model names are retained.

MyMemory may store submitted texts long term. The application uses only the translation query and does not submit additional dictionary entries. There is no automatic provider switch. Existing API keys, ChatGPT connections, models and dictionaries are retained. INI saving retains Polish characters through Unicode; when necessary, the backed-up output is saved as UTF-16 with BOM. Actual EEP processing of this encoding was not tested.

90 local checks passed. The supplied sample INI was imported, translated through real MyMemory calls and saved as a copy; the original remains unchanged. Review machine translations of technical terminology before use.

Setup and workflow ​

  1. Download the Windows ZIP above and extract all files.
  2. Start INI Edit Translate 2026.exe from the extracted directory, keeping its DLLs and language directories together.
  3. Open About → Settings → Translation settings. Select MyMemory, OpenAI API or ChatGPT plan. MyMemory needs no login; email is optional.
  4. Open a backed-up file in Read only mode first.
  5. Use Read and translate or a translation button. Select the source language for axes and signal functions.
  6. Review the preview and model texts, then save explicitly.

The information dialog selects the reviewed Info.de.rtf, Info.en.rtf or Info.fr.rtf to match the interface language. The historical Info.rtf is retained unchanged. Current help describes OpenAI translation and the restored reference program.

GitHub updates ​

Choose About → Check for updates to query the latest public GitHub release. There is no automatic startup check. Only a newer stable version is offered, with its version number and release notes.

Download and install downloads the Windows ZIP and SHA-256 checksum. Download and package validation can be cancelled and finish before the application closes. Save open files and close Info_trans before installation. Installation requires confirmation. A separate helper waits for the editor to exit, backs up existing files and installs the package.

Settings and the encrypted OpenAI key are retained. Existing reference-help FDB, CSV, DAT and configuration files, plus the original Info.rtf, are backed up and not replaced. Your model files are left intact. On installation failure, the updater attempts to restore files already replaced and records the result. Backups and reports are stored under %LOCALAPPDATA%/UGSo/IET2026/updates/<identifier>/.

No server credentials are needed. Checksums verify integrity; no additional digital package signature is implemented. 36 isolated update checks cover downloads, cancellation, package paths, retained data, locked files and rollback after partial writes.

Second program: Info_trans ​

The package also includes help/Info_trans.exe. Reference help in the main editor opens it in the selected language. The actual IET2.FDB and its native Firebird 2.5.8 runtime were restored from the 2019 archive. No separate Firebird server installation is required.

Missing or unloadable components are reported and SQL import is then disabled. A local database backup precedes an available manual SQL import. Automatic application updates remain disabled.

Data and privacy ​

Old registrations and personal databases are not imported. Settings are stored separately for each Windows user. OpenAI configuration and file backups are under %LOCALAPPDATA%/UGSo/IET2026/.

Windows DPAPI encrypts the API key for the current Windows account. Selected texts are sent to OpenAI with store: false. Internet access and separate API billing are required; a ChatGPT subscription does not replace API billing.

Updates and verification ​

GitHub updates are started manually and require installation confirmation. The old update server is not used. Google, LEO, Linguee and DeepL are no longer offered.
