USB Extender pour Home Assistant ​

0.1.38 · Version de test publique · Raspberry Pi · Mise à jour du 23 novembre 2026

Un clavier USB connecté au Raspberry Pi peut servir de commande pour Home Assistant ou ioBroker. USB Extender lit les entrées et les publie vers trois courtiers MQTT simultanément au maximum. L’interface Web sert à la configuration et peut ensuite être arrêtée ; le service USB/MQTT continue indépendamment.

GitHub / README allemand et anglais · ZIP 0.1.38 et SHA256 · Modifications

Il s’agit d’un programme autonome pour Raspberry Pi, pas d’une application HA à installer dans le magasin, ni d’un logiciel officiel de Home Assistant ou Elgato. Ce n’est pas un tunnel USB sur IP : les imprimantes et caméras ne sont pas transmises comme périphériques USB distants.

Les captures fournies par l’utilisateur proviennent du montage réel en 0.1.5. L’interface est actuellement en allemand. Cliquer sur les images larges pour les ouvrir à leur taille d’origine.

Nouveautés 0.1.38 : commandes système MQTT et cartes HA ​

L’interface Web peut maintenant être démarrée et arrêtée par MQTT lorsque son service Web est arrêté. Démarrage automatique Web, sauvegarde et demande d’état sont également disponibles. Dans MQTT-Broker, activez explicitement la commande système du courtier souhaité et enregistrez ; les courtiers existants restent initialement inchangés. Avec la découverte HA, deux interrupteurs, un bouton de sauvegarde et deux capteurs d’état apparaissent sous USB Extender.

Les commandes utilisent usb-extender/global/web/set et usb-extender/global/web/autorun/set avec ON/OFF ; sauvegarde et demande d’état utilisent usb-extender/global/backup/set et usb-extender/global/web/status/set avec PRESS. Les retours séparés sous usb-extender/global/state/ sont webrun, autorun, state et backup. Ne pas conserver les commandes avec Retain. Plusieurs Extenders sur le même courtier réagissent ensemble à ces topics globaux.Configuration et formats exacts des retours.

USB Extender Cards 0.1.0 ​

Le paquet de cartes indépendant sur GitHub propose des présentations inspirées de Mushroom et Bubble, sans installation supplémentaire de ces cartes. Ajoutez le dépôt personnalisé de tableau de bord dans HACS ou chargez manuellement le JavaScript de la version avec ZIP. Dans l’éditeur visuel, utilisez Affectation automatique, saisissez l’adresse Web et choisissez la présentation. Les identifiants d’entités viennent du registre ; si plusieurs Extenders sont présents, choisissez explicitement l’appareil.

Ouvrir l’interface Web ouvre un onglet d’attente au clic, demande le démarrage, puis charge l’URL après confirmation. Interrupteurs Web/démarrage automatique, sauvegarde et états sont inclus. Un lien manuel est proposé si les fenêtres sont bloquées. La carte utilise la session HA existante, sans jeton supplémentaire. L’installateur Pi ne modifie aucun tableau de bord ; l’onglet Système contient un lien vers le paquet.

Ces images sont des aperçus locaux. La logique et les parcours du navigateur ont été testés avec des entités HA simulées ; un nouveau test réel HA ou Companion reste à effectuer. L’interface de la carte prend en charge DE/EN/FR.

Déjà en 0.1.36 : affichage compact des disques USB ​

Les clés et autres supports de stockage USB sont reconnus par leur classe USB de périphérique ou d’interface. Les nouveaux supports n’ont aucune cible MQTT cochée et leurs entrées sont désactivées. Les réglages d’entrée, d’affichage et de réaffectation sans rapport avec le stockage ne sont pas proposés.

Dans USB / Périphériques virtuels, deux cases sont disponibles :

  • System : la ligne repliée affiche le nom et Systemlaufwerk (disque système).
  • Hidden : la ligne repliée affiche uniquement le nom.

Les deux options s’excluent. Dépliez la ligne pour la modifier, puis utilisez Enregistrer. Sans ces options, l’entrée s’ouvre dépliée. La classification reste disponible pour les supports enregistrés hors ligne. System est un marquage manuel, pas une détection automatique de la partition de démarrage. Hidden conserve le périphérique dans la liste.

Ces options changent uniquement l’affichage : aucun montage, formatage ni écriture sur le disque. Les cibles MQTT existantes, affectations, autres appareils et appairages Mobile sont conservés. L’indicateur d’espace libre en haut mesure toujours le système de fichiers contenant le répertoire de données du programme.

Déjà en 0.1.35 : scanners de codes-barres/QR et tags HA ​

Les scanners USB HID de type clavier disposent d’un mode distinct, désactivé par défaut. Dans USB / Virtuelle Geräte, autoriser le périphérique et le mode scanner, choisir la disposition DE/US, la fin par Entrée/Tab/pause, le topic et les courtiers cibles, puis enregistrer. Exemple : barcodescanner. La pause par défaut est de 500 ms ; les entrées incomplètes ou trop longues sont rejetées. Les scanners série, Unicode arbitraire et séquences de contrôle GS1 ne sont pas pris en charge.

Chaque lecture complète publie du texte brut sans retain. Un même code déclenche un événement à chaque lecture ; les zéros initiaux fournis par l’appareil sont conservés. Aucun lien ni commande n’est exécuté. L’aperçu montre le dernier texte brut. Les actions de touches existantes de cet appareil sont suspendues en mode scanner, mais leurs affectations restent enregistrées.

Où apparaissent les lectures dans Home Assistant ? ​

Activer la découverte pour le courtier HA. Le scanner est annoncé par l’intégration MQTT tag native. Les lectures produisent des événements tag_scanned, pas des entités capteurs ordinaires. Dans Paramètres → Tags, nommer le tag et créer une automatisation de tag, par exemple pour basculer une lampe. L’action est définie dans HA. USB Extender n’a pas besoin de jeton d’accès HA.

En option, https://www.home-assistant.io/tag/atelier devient l’identifiant atelier. Les autres textes restent inchangés. ioBroker reçoit le texte sur le topic choisi ; la découverte peut rester désactivée pour son courtier.

Test pratique réussi avec l’Aplic 305045 ​

Le 22 novembre 2026, quatre lectures réelles ont été effectuées sur Raspberry Pi .112 avec 0.1.35 : deux fois le même code-barres, un QR texte et un QR de tag HA. Chaque lecture a été transmise à trois courtiers ; HA .193 a reçu quatre événements natifs distincts. La réception dans ioBroker sur barcodescanner est également confirmée. Les codes répétés ne sont pas supprimés. À la fin, services USB/MQTT et Web actifs, sans redémarrage ni erreur signalée. Aucune action HA n’a été exécutée.

Test complet et limites. La sauvegarde vérifiée avant le test n’était plus au chemin enregistré lors de la comparaison finale ; ce test ne fournit donc pas de preuve finale par empreintes des métadonnées. L’agent n’a modifié ni réglages ni appairages. La découverte après redémarrage et désactivation reste à vérifier sur le matériel.

Déjà en 0.1.31 : Logitech Touchpad T650, périphériques et droits d’installation ​

0.1.31 inclut les modifications auparavant locales des versions 0.1.29 et 0.1.30. Tasten & Anzeigen regroupe les périphériques par ordre alphabétique, repliés initialement. Un seul groupe et une seule touche restent ouverts à la fois. Les touches de volume, de luminosité et d’éclairage du clavier proposent un filtre de pas 1–5 sous Bearbeiten : 3 envoie les pas 3, 6, 9, etc. Le relâchement arrête la répétition du volume, même lorsque certains pas sont ignorés.

Les numéros de série uniques et les identifiants Logitech HID++ disponibles conservent l’affectation lors d’un changement de port. Sans identifiant unique, affecter explicitement le nouvel appareil USB à une entrée hors ligne enregistrée ; touches, pages et topics sont conservés. La suppression confirmée par la corbeille sauvegarde les métadonnées et conserve les icônes partagées. Révoquer séparément la confiance Mobile.

Logitech Touchpad T650 : glissement à un doigt et X/Y ​

Dans USB / Virtuelle Geräte, autoriser le T650, activer Touchpad-Gesten auswerten, puis ouvrir Ein-Finger-Slide und optionale X/Y-Werte. Régler la sensibilité et la fréquence maximale, enregistrer, puis apprendre les directions souhaitées. Le pilote Linux doit fournir le multitouch de type B ; un simple événement de clic ne suffit pas.

MouvementAction à apprendre
Gauche / droiteTOUCHPAD_SLIDE_LEFT / TOUCHPAD_SLIDE_RIGHT
Haut / basTOUCHPAD_SLIDE_UP / TOUCHPAD_SLIDE_DOWN
Haut gauche / haut droiteTOUCHPAD_SLIDE_UP_LEFT / TOUCHPAD_SLIDE_UP_RIGHT
Bas gauche / bas droiteTOUCHPAD_SLIDE_DOWN_LEFT / TOUCHPAD_SLIDE_DOWN_RIGHT

Huit secteurs de 45° distinguent les directions. La sensibilité 1–10 définit le mouvement nécessaire : 10 est plus sensible, 1 demande un mouvement plus ample ; valeur initiale 5. La fréquence 1–30/s est une limite par flux d’actions directionnelles et par paire X/Y, initialement 10/s. Une paire X/Y représente deux messages MQTT par courtier cible ; les autres canaux de touche activés peuvent produire des messages supplémentaires.

X/Y est désactivé initialement. L’activation suivie de l’enregistrement crée des topics lisibles, par exemple t650-touchpad/x et t650-touchpad/y. Des topics personnalisés sont possibles ; les topics enregistrés restent identiques après renommage. Les deux axes utilisent les courtiers cibles de l’appareil et envoient des nombres entiers 0–100, sans JSON. X : gauche 0, droite 100 ; Y : haut 0, bas 100. Il s’agit de la position absolue sur le pavé tactile.

Après un glissement reconnu, aucun tapotement supplémentaire n’est produit au relâchement. Les positions inchangées ne sont pas retransmises. Une dernière paire en attente peut suivre le relâchement au prochain intervalle autorisé. Plusieurs doigts, un clic mécanique, une perte d’entrée ou une modification des options annulent les valeurs en attente. Pas de conservation MQTT ni de renvoi aux courtiers précédemment déconnectés ; X/Y reste muet pendant l’apprentissage.

Logitech Touchpad T650 : test réel et limites ​

Test du 22 novembre 2026 avec un véritable T650 et un Raspberry Pi 4 en 64 bits :

  • Les huit directions attendues sont reconnues ; aucun tapotement pendant les glissements. Un test séparé a produit quatre tapotements, sans sortie X/Y.
  • Trois courtiers MQTT de test locaux ont reçu chacun 752 messages identiques, dont 200 paires X/Y. Les axes transmettent des entiers dans la plage 0–100.
  • En direct : sensibilité 5, limite de 10/s ; intervalle minimal 0,100000 s.
  • Relecture des mêmes enregistrements réels : la sensibilité 1/5/10 a produit 33/38/39 actions lors des mouvements rapides. Les limites 1/5/30 ont donné des intervalles X/Y minimaux de 1,006229 / 0,201979 / 0,037912 s. Cela ne remplace pas un nouveau test en direct des réglages Web ou de nouveaux gestes à chaque valeur.
  • Deux événements de direction voisine et un appui long ont aussi été enregistrés. Aucune garantie d’une direction exclusivement unique pour chaque geste, ni de validation générale des autres gestes multitouch ou modèles de pavés tactiles.
  • Seul le T650 a été évalué ; K400/T400 sont inchangés. La mesure isolée utilisait des réglages temporaires et des courtiers de boucle locale, sans cible de production.

Rapport complet du T650 et de l’installation. L’outil de mesure a également été corrigé : la purge bornée consomme le générateur evdev ; un message de départ et un compte à rebours rendent la fenêtre de mesure visible.

Correction de l’installateur et conservation des données ​

Un umask 077 hérité pouvait rendre le nouvel environnement Python inaccessible au compte de service (Permission denied à l’étape 6). L’installateur définit désormais umask 022 pour les fichiers du programme et umask 077 pour les archives privées. Aucune modification globale des droits des données utilisateur n’est requise.

L’installation suivante sur le Pi a été vérifiée : CLI et service actif indiquent 0.1.31, USB/MQTT et Web sont actifs, avec NRestarts=0 chacun. Mobile est actif et la liste d’erreurs est vide. Cinq contrôles SHA256 de config.json, switches.json, mobile-identity.json, mobile-trust.json et mobile-devices.json confirment des réglages et jumelages identiques octet par octet. Une sauvegarde a précédé l’installation. Ce contrôle du démarrage ne constitue pas un nouveau test d’endurance après installation.

Installation sur le Pi ​

Configuration conseillée : Raspberry Pi 4, Raspberry Pi OS Lite 64 bits, Bookworm ou ultérieur, Python 3.11+, systemd, sudo et Internet pour apt/PyPI. Plusieurs appareils avec écran peuvent nécessiter un hub USB alimenté séparément. Le système Pi OS 32 bits n’a pas encore été validé en pratique.

Copier le ZIP sur le Pi, ouvrir un terminal dans son dossier de téléchargement et lancer :

bash
sudo apt-get update && sudo apt-get install -y unzip
unzip USB-Extender-Home-Assistant-0.1.38-Raspi4.zip
cd USB-Extender-Home-Assistant-0.1.38
sudo bash install.sh

Lors d’une mise à jour, il sauvegarde les données existantes dans /var/backups/ et conserve réglages et icônes. Le ZIP n’est pas une image système entièrement utilisable hors ligne. Pour une mise à jour, extraire le nouveau ZIP séparément et lancer son installateur.

Configurer les courtiers et apprendre les touches ​

  1. Dans MQTT-Broker, saisir hôte, port et identifiants éventuels. Activer les connexions souhaitées et enregistrer. Chaque courtier dispose de sa connexion ; une touche peut envoyer aux trois.
  2. Activer la découverte pour HA. Pour ioBroker, choisir Aus – nur MQTT-Daten senden afin que son adaptateur de découverte HA ne signale pas de déclencheurs non pris en charge.
  3. Dans USB / Virtuelle Geräte, nommer et autoriser l’appareil, choisir ses cibles et enregistrer.
  4. Dans Tasten & Anzeigen, choisir l’appareil puis Anlernen starten. Appuyer et relâcher chaque touche souhaitée. Les répétitions et touches déjà présentes ne créent pas de doublons.
  5. Choisir Anlernen beenden → Tasten übernehmen → Speichern. Les nouvelles lignes sont alors actives. Pendant l’apprentissage, l’appareil sélectionné n’envoie aucune action MQTT.
  6. Modifier les cases des canaux, les topics ou les noms par ligne. Bearbeiten ouvre le choix des courtiers, le comportement Switch et les délais. Les nouveaux canaux supplémentaires des lignes existantes sont initialement désactivés ; les nouvelles touches apprises ont tous les canaux préparés.

Si le navigateur se ferme pendant l’apprentissage, la pause expire au plus tard après 15 secondes sans nouvelle confirmation. Les brouillons d’apprentissage restent uniquement dans le navigateur jusqu’à leur application et enregistrement. Les affectations déjà enregistrées sont conservées.

Topics et fonctions des touches ​

Le nom Trust1 et la touche F1 donnent par exemple trust1-key-f1/press. Les noms sont adaptés à MQTT ; les caractères allemands de « Büro » deviennent buero. Les noms identiques reçoivent au besoin -2, -3, etc. Les topics enregistrés restent stables après un changement de nom et sont identiques sur tous les courtiers choisis. Ils sont modifiables individuellement.

Suffixe après trust1-key-f1Valeur et fonction
/presspress immédiatement à l’appui
/releaserelease au relâchement
/press-plus, /release-plusMême action, puis message vide après 50 ms sur ce canal
/switchPremier appui ON, suivant OFF ; relâcher ne change rien
/stateTouche enfoncée ON, relâchée OFF
/buttonclick, double_click ou hold selon le geste
/button-plusMême action Button, puis vide après 50 ms
/click, /double-click, /holdLe geste individuel correspondant

Le mot plus est écrit en toutes lettres, car + est un caractère générique MQTT. Les onze canaux sont activables séparément. Seuls les canaux Plus reviennent au vide ; vide ne signifie pas relâchement physique. Les valeurs Switch sont conservées dans switches.json après un redémarrage et resynchronisées à la reconnexion.

Clic/double-clic/appui long : un clic attend la fenêtre de double-clic (300 ms après relâchement par défaut). Un second clic dans cette fenêtre produit uniquement double_click. Un appui de 700 ms produit hold une fois, sans clic au relâchement. Maintenir le second appui remplace la séquence en attente par Hold. Les délais sont réglables par touche. La répétition native du clavier ne compte pas comme nouveau clic ou nouvel appui sur Switch.

Volume : les canaux Press/Press+ actifs peuvent se répéter pendant l’appui, par défaut après 500 ms toutes les 150 ms. Le relâchement arrête la répétition ; une limite de sécurité de 30 secondes s’applique aussi. L’automatisation HA ou la logique ioBroker définit le pas de volume. Press/Release restent immédiats, indépendamment de la reconnaissance différée des gestes Button.

Les messages utilisent QoS 0 sans Retain. Les entrées hors connexion ne sont pas rejouées. Plusieurs canaux actifs peuvent déclencher plusieurs automatisations associées ; choisir le canal adapté à la fonction unique souhaitée.

Affichage dans Home Assistant et ioBroker ​

La découverte HA regroupe toutes les touches sous le nom choisi avec un identifiant stable commun. Les actions sont des déclencheurs d’appareil avec filtrage de valeur. Switch et l’état d’appui sont des capteurs binaires indiquant un état ; commander un autre appareil nécessite une automatisation ou une affectation.

Dans la capture utilisateur, Switch est activé après l’appui et l’état d’appui est désactivé après relâchement. Des valeurs inconnues peuvent apparaître avant le premier message d’état reçu ; cela ne prouve pas une détection défectueuse.

Avant les premiers messages d’état

Dans ioBroker, les points de données séparés apparaissent sous l’adaptateur MQTT à la première réception de chaque topic. La capture montre des valeurs simples : press, release, click, hold, ON et OFF. Les canaux Plus affichent ici (null) après leur remise à vide. C’est attendu ; le point de données reste présent. Un point double-clic apparaît seulement après l’envoi du message correspondant. Les anciens points contenant l’événement JSON initial ne sont pas modifiés automatiquement. Les configurations de découverte restent volontairement en JSON.

Stream Deck et appareils similaires ​

Le pilote intégré python-elgato-streamdeck 0.10.0 connaît notamment Original/MK.2, Mini, XL, Neo, Pedal et Plus. Cette liste décrit le pilote, pas des essais matériels physiques déjà effectués dans ce projet.

  • Touches avec écran : icônes/texte personnels, luminosité par appareil, retour d’état MQTT pour changer une icône et commandes d’affichage ciblées.
  • Touches : Press/Release, clic/double-clic/appui long, Switch et état d’appui comme ci-dessus.
  • Molettes présentes : sens de rotation et appui comme entrées.
  • Écran tactile présent : événements tactiles ; pas d’éditeur d’écran librement composé.
  • Pedal et autres modèles sans écran : entrées, mais pas d’icônes sur touches d’affichage.
  • Jusqu’à huit pages indépendantes par deck avec touches de navigation ; profils supplémentaires encore à réaliser. Les icônes animées sont implémentées.

Éditeur graphique et liste compacte des touches ​

L’onglet Stream Deck reste visible hors ligne et conserve l’éditeur et la dernière grille. Pages et navigation sur le deck ​

USB / Virtuelle Geräte regroupe les périphériques USB et les decks Mobile virtuels jumelés. Chaque téléphone/tablette conserve ses pages et affectations.

  1. Dans Stream Deck, Neue Seite ajoute une page, jusqu’à huit par appareil. Les numéros continuent : 1–15 puis 16–30 pour 15 touches ; 1–64 puis 65–128 pour 8×8. La grille vient toujours de l’appareil ou de l’application Android.
  2. Choisir une touche, puis Gestaltung → Tastenfunktion : MQTT, Vor (suivante), Zurück (précédente), Home (première) ou Gehe zu (aller à) avec Zielseite (page cible). Après Speichern, la touche navigue sur la tablette sans envoyer d’action MQTT.
  3. Seitennummer anzeigen ajoute un compteur. Home revient à la page 1 ; suivante/précédente s’arrêtent aux limites. Les boutons de l’éditeur changent seulement l’aperçu, pas la page réellement affichée sur l’appareil.
  4. Aktuelle Seite löschen supprime les affectations de cette page après confirmation ; la page 1 est protégée. Enregistrer pour appliquer. Les IDs/topics des autres pages restent stables même si les numéros affichés changent. Les cibles suivent leur page renumérotée ; supprimer la cible redirige la touche vers la page 1.

La navigation conserve les affectations MQTT existantes ; choisir de nouveau MQTT les réactive. Les nouvelles pages reçoivent des topics stables tels que tablet-page-2-key-0/press ; ceux de la première page restent inchangés. Un redémarrage du service ouvre la page 1. Changer de page termine les touches maintenues et clics en attente ; un retour MQTT d’une autre page n’écrase pas la page visible. Les champs d’apparence et de couleur sont plus compacts.

Stream Deck Mobile : optionnel et expérimental ​

  1. Activer Mobile-Server, saisir l’adresse accessible du Pi et le port (28198 par défaut), puis enregistrer.
  2. Choisir Kopplung starten · QR-Code et scanner avec Ajouter un ordinateur dans Android.
  3. Comparer l’empreinte à six chiffres. Seulement si elle correspond, cliquer sur Gerät vertrauen dans Mobile-Verbindungen. La confiance reste enregistrée.
  4. Ouvrir un deck dans Android, autoriser l’appareil Mobile dans USB Extender et enregistrer. Affecter l’apparence et MQTT dans l’éditeur Stream Deck.
  5. Régler lignes et colonnes dans Android. L’éditeur suit la grille annoncée jusqu’à 8×8 ; aucun remplacement de grille côté éditeur.

Le service Mobile fonctionne indépendamment du service Web. Le jumelage exige l’interface Web ; elle peut ensuite être arrêtée. Port WebSocket local, sans découverte cloud/Bonjour ni modification des droits d’achat Pro de l’application.

Mobile-Verbindungen affiche compteurs d’images/métadonnées, ping/pong et dernière déconnexion. Pour des touches statiques inchangées, les compteurs d’images doivent cesser d’augmenter. Le maintien de connexion n’envoie pas de nouvelles images ; les animations en transmettent volontairement. L’utilisateur a confirmé jumelage, icônes, couleurs et 8×8. L’essai de 15 minutes avec navigation et repos ci-dessous est réussi.

0.1.28 : essai de 15 minutes réussi ​

Les images Mobile sont envoyées en petits lots : au plus quatre images par itération avec un budget de travail souple de 25 ms. Les entrées et le heartbeat sont traités entre les lots. Un envoi réseau déjà commencé peut durer plus longtemps ; le délai heartbeat reste de 20 secondes. Le journal de déconnexion ajoute Ping/Pong, type/âge du dernier message et images en attente, sans contenu des messages ni identifiants de connexion.

Le 22 novembre 2026, une vraie SM-T580 avec grille 8×8 et deux pages a été observée pendant 900 secondes : plusieurs passages suivante/précédente, puis environ 14 minutes au repos. Bibliothèque d’icônes, animations et import de packs ​

Sélecteur graphique au lieu de longues listes : icônes normales/enfoncées, fonds et retours MQTT utilisent le même sélecteur. Déplier un pack, rechercher, choisir une icône et Übernehmen (ou double-cliquer). Abbrechen/Échap conservent l’ancien choix ; Speichern enregistre ensuite. Seules les miniatures PNG 48×48 sont chargées, première image d’une animation, avec au plus 96 cases visibles par page de pack. Le Pi les crée à la demande dans icons/.cache/thumbnails/ ; le Pi et le navigateur authentifié réutilisent le cache.

Les mêmes IDs/contenus apparaissent une fois par pack ; les noms alternatifs restent recherchables. Originaux et IDs enregistrés ne sont ni supprimés ni réécrits. Styles distincts et packs noir/blanc restent séparés. MDI-Favoriten hinzufügen · 40 Icons importe, sur demande, le pack SteelBlue fourni avec 20 paires marche/arrêt. Aucune installation ou affectation MQTT automatique ; choisir soi-même les icônes normales/enfoncées ou les retours.

Déplier les packs séparément ou rechercher noms de packs, fichiers et sous-dossiers. Survol/focus affiche nom et aperçu. Miniatures 48×48 dans des cases compactes 52×52 ; la licence figure une fois dans l’en-tête du pack. Espace libre et total en haut de page.

Importer images seules, dossiers du navigateur, dossiers sur le Pi et packs locaux ZIP, .streamDeckIconPack ou .streamDeckPlugin. Les plugins fournissent seulement les images des dossiers pris en charge, jamais le code exécutable. Les métadonnées JSON reconnues donnent le nom du pack, sinon le nom du dossier/de l’archive est utilisé. Les noms et sous-dossiers d’origine sont conservés. Aucun téléchargement automatique du Marketplace ; respecter les droits d’utilisation.

PNG/JPEG et SVG statiques sont pris en charge. GIF/WebP s’animent dans les états normal et enfoncé, jusqu’à 120 images et 10 images/s. Les animations SVG ne sont pas lues ; les fonds restent statiques. La lecture réelle doit être vérifiée par modèle.

Originaux : /var/lib/ugso-usbhub/icons/IconPacks/ ; index : icons/index.json ; aperçus dérivés : icons/.cache/. La suppression d’un pack crée d’abord une sauvegarde et bloque les packs utilisés par des affectations enregistrées.

Depuis 0.1.22 : enregistrer l’index une fois à la fin et créer aperçus/données d’animation à la demande. Les dossiers du navigateur sont envoyés en un ZIP, en conservant plusieurs packs et leurs chemins. La progression utilise les vrais compteurs du serveur. Terminer un import en cours avant toute mise à jour.
