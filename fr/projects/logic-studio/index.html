Logic Studio ​

0.1.12 – mise à jour publique de test, 8 novembre 2026. Interface et documentation sont désormais disponibles en DE/EN/FR. Logic Studio est une application HA autonome pour les plans à blocs fonctionnels, indépendante de Grafik Visual Studio et Blocks for HA. Le canevas React Flow conserve ses blocs personnalisés, connexions typées, zoom et MiniMap ; bibliothèques et licences sont incluses localement.

Version de test

Installer d’abord sur un système de test et créer une sauvegarde complète. Les propriétés natives détaillées sont actuellement modifiables en JSON. L’application ne réécrit pas les automatisations/scripts dans HA et ne commande aucun appareil. Vérifier et installer soi-même les sorties générées.

HA Logic Studio Pro ​

HA Logic Studio Pro est une application Home Assistant autonome dans le dépôt commun UGSo. Elle s’appuie sur Logic Studio et sur l’expérience acquise avec ioBroker.

Fonctionnalités disponibles

  • Diagramme fonctionnel : Relier les blocs, afficher les signaux aux entrées et simuler le diagramme. Sur le serveur HA, l’exécution peut réagir aux changements ou suivre un cycle fixe.
  • Règles et Blocks A : Créer des automatisations dans un éditeur visuel et les exporter au format YAML de HA.
  • Blocks JS, JavaScript et TypeScript : Modifier la logique, la tester avec des valeurs simulées et l’exécuter sur le serveur HA.
  • YAML HA : Modifier, valider et exporter les automatisations et les scripts.
  • Gestion des projets : Enregistrer les projets et les dossiers sur le serveur pour chaque utilisateur HA.
  • Choix de la langue : Les éditeurs sont disponibles en allemand, en anglais et en français.

0.1.133 · États des capteurs et nouveaux plans fonctionnels ​

System → Définir l’état du capteur est disponible dans Blocks A et Blocks JS. Choisis un sensor.* existant et connecte un nombre, un texte ou un calcul. Le sélecteur de style HA affiche le nom, l’identifiant et l’état des capteurs. L’unité, la classe d’appareil et les autres attributs sont conservés. Le capteur nécessite l’autorisation WRITE ; READ seul ne suffit pas.

Blocks JS utilise ha.setSensorState("sensor.example", 42). Blocks A exporte l’événement HA natif logic_studio_set_sensor_state avec entity_id et state. L’application Studio active le reçoit et vérifie la même autorisation WRITE. Cette entrée interne ne nécessite pas d’autorisation EVENT générale. Sans l’application, la demande d’écriture n’est pas traitée. Les erreurs du pont apparaissent dans le journal de l’application ; émettre l’événement ne confirme pas la réussite de l’écriture.

Le comportement correspond à Outils de développement → États : aucune commande à l’appareil et aucun nouveau capteur permanent. Une intégration ou un redémarrage de HA peut remplacer la valeur. Les tests JS simulent l’écriture ; l’aperçu YAML n’écrit rien.

Nouveau projet → Plan fonctionnel demande désormais un nom et un dossier à chaque création. Plusieurs plans indépendants sont possibles et commencent vides. Les plans, dossiers et réglages existants sont conservés. Annuler ne crée aucun projet.

Vérifié : 50 tests Node et 12 tests du serveur. Après sauvegarde sur Home Assistant 2026.11.3, Blocks JS a écrit 40 + 2 sous forme de 42 W ; les données d’événement générées par Blocks A ont défini 43 W via le pont. Les attributs ont été conservés. Une écriture a été refusée après retrait de WRITE. Deux nouveaux plans sont restés distincts après rechargement et le plan existant a été conservé. Les autorisations initiales ont été rétablies. Les libellés des blocs ont été vérifiés en DE/EN/FR.

0.1.132 · Quatre autorisations runtime séparées ​

Dans Paramètres → Applications → HA Logic Studio Pro → Configuration, une case « Tous » distincte est disponible pour READ, WRITE, EVENT et TOPICS. Les libellés sont disponibles en DE/EN/FR.

CaseListe associéeEffet si activée
runtime_read_all · READruntime_read_entitiesLire tous les ID d’entités HA valides, y compris les nouvelles entités.
runtime_write_all · WRITEruntime_write_entitiesAutoriser toutes les cibles pour les actions runtime prises en charge.
runtime_events_all · EVENTruntime_eventsAutoriser tous les types d’événements pris en charge ; le script s’abonne toujours à des noms précis.
runtime_mqtt_all · TOPICSruntime_mqtt_topicsAutoriser la publication sur tous les sujets MQTT concrets.

Toutes les cases sont désactivées par défaut. Si une case est activée, seule la liste associée est ignorée ; ses entrées restent enregistrées et s’appliquent à nouveau après désactivation. Le formulaire HA standard permet toujours de modifier ces listes et ne les grise pas automatiquement. READ, WRITE, EVENT et TOPICS sont configurés indépendamment.

Pour un capteur signalant un accès en lecture non autorisé, READ suffit. Après l’enregistrement, redémarrer le projet concerné et, si nécessaire, l’application. WRITE seul n’active pas la lecture générale. La validation des ID/actions, les sujets MQTT sans +/# et la restriction existante logic_studio_* pour les événements envoyés restent en place.

Connexions à la souris et mini-vue ​

Maintenir le bouton de la souris sur une borne colorée, faire glisser vers une borne opposée compatible puis relâcher. Le curseur devient une croix et un aperçu du lien suit la souris.
