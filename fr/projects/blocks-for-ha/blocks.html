Catalogue des blocs ​

Depuis 0.1.66, les valeurs de texte simples sont vides dans toutes les catégories : sujet/message MQTT, contenus d’objets/listes, conversions et valeurs de remplacement sans exemples. Réponses Assist et texte Jinja utilisent aussi des champs sur une ligne. Saisir les valeurs requises avant l’export. Séparateurs, structures JSON valides et réglages numériques, horaires et d’actions conservés. L’ouverture d’un projet conserve ses textes, y compris les sauts de ligne existants. Les éditeurs multilignes de code Jinja et JSON restent disponibles.

Dans le menu Variables, les options Définir, Incrémenter et Lire la variable apparaissent pour chaque variable créée. Exemple dans une séquence d'actions : Définir test à 10 → Incrémenter test de 1 → Journaliser un message d'information avec la variable test. Le message utilise alors la valeur 11. Avant toute incrémentation, la variable doit être définie en tant que nombre. Les variables inexistantes, le texte (y compris "10"), les valeurs booléennes ou null ne sont pas convertis automatiquement et ne sont pas initialisés avec 0 ; l'évaluation Jinja dans HA échouera alors. La simple création d'une variable ne lui attribue aucune valeur. Le format JSON intègre le bloc d'incrémentation ; notre format de sortie YAML spécifique est reconnu comme un bloc d'incrémentation lors de l'importation. Dans le menu Variables → Créer une variable…, créez par exemple leistung. Les noms peuvent contenir des lettres, des chiffres et _, mais ne doivent pas commencer par un chiffre. Placez le bloc « Définir » dans la section Alors et associez-y un nombre ou un modèle (template). Ensuite, insérez le bloc « Lire » dans une action de journalisation (log). La création seule n'attribue pas encore de valeur. Les variables sont valables pour la durée de l'exécution de l'automatisation HA ; elles ne remplacent pas les « assistants » (helpers) stockés de manière permanente.

Exemple : Définir leistung (puissance) via un modèle (template) avec {{ states('sensor.leistung') | float(0) }}, suivi d'un message de journal (Log Info) : Variable de puissance. HA lit le capteur au moment de l'affectation et utilise cette valeur à l'étape suivante. Une condition de type « template » peut, par exemple, vérifier {{ states('sensor.leistung') | float(0) > 100 }}.

Le renommage met à jour les blocs de variables associés. Les noms présents dans des textes Jinja saisis manuellement doivent être modifiés manuellement. Les variables d'action ne sont disponibles qu'après leur affectation ; elles ne sont donc pas accessibles dans les conditions d'automatisation situées en amont. La vérification des blocs porte sur la structure et le YAML, mais ne concerne ni la syntaxe Jinja ni l'existence des entités HA. L'importation prend en charge, pour chaque valeur de variable, les types suivants : texte/template, nombre, booléen ou « null ». Depuis 0.1.34, il est possible d'inclure plusieurs entrées au sein d'un bloc JSON commun. L'utilisation de listes ou d'objets comme valeurs, ainsi que la définition de variables au niveau de l'automatisation, restent proscrites. Variables natives HA et validité.

Si nécessaire, convertissez les états des capteurs dans le modèle (template) à l'aide de float ou int. Dans un champ d'expression, une seule sortie Jinja est autorisée, par exemple : {{ states('sensor.leistung') | float(0) }}. Les instructions multilignes et le texte mixte restent utilisables dans un bloc de valeur de modèle (template) dédié. Les sélections de valeurs dynamiques ne sont pas conçues pour servir de limites numériques fixes ou de durées d'attente.

Les projets JSON préservent les formes des blocs et leurs connexions. Le format YAML conserve la sémantique native : lors de la réouverture, les comparaisons et les sélections de valeurs apparaissent sous forme de blocs modèles (templates), tandis que les opérateurs ET/OU/NON sont représentés par des groupes de conditions.
